## Бот для создания саммари документов

Telegram-бот для автоматического создания саммари из различных типов документов с использованием DeepSeek AI.

## Поддерживаемые форматы документов

Бот поддерживает следующие форматы документов:

### Офисные документы
- **PDF** - PDF документы
- **DOCX** - Word документы (новый формат)
- **DOC** - Word документы (старый формат)
- **PPTX** - PowerPoint презентации
- **ODT** - OpenDocument Text
- **ODP** - OpenDocument Presentation

### Таблицы
- **XLSX** - Excel таблицы (новый формат)
- **XLS** - Excel таблицы (старый формат)
- **CSV** - CSV файлы

### Текстовые форматы
- **TXT** - Текстовые файлы
- **RTF** - Rich Text Format
- **MD** - Markdown файлы
- **HTML/HTM** - HTML файлы

**Всего: 14 форматов**

## Установка

1. Установите зависимости:
```bash
pip install -r requirements.txt
```

**Примечание:** Для работы с форматом `.doc` может потребоваться установка дополнительных системных зависимостей:
- На Linux: `antiword` или `catdoc`
- На Windows: обычно работает без дополнительных установок
- На macOS: может потребоваться установка через Homebrew

2. Создайте файл `.env` и укажите токены:
```
BOT_TOKEN=ваш_токен_бота
DEEPSEEK_API_KEY=ваш_ключ_deepseek
YOOKASSA_SHOP_ID=ид_магазина_юкасса
YOOKASSA_API_KEY=секретный_ключ_юкасса
YOOKASSA_RETURN_URL=https://t.me/ваш_бот
```

## Запуск

```bash
python bot.py
```

### Переменные окружения для оплат (ЮКасса)
- `YOOKASSA_SHOP_ID`
- `YOOKASSA_API_KEY`
- `YOOKASSA_RETURN_URL` (URL возврата после оплаты, напр. `https://t.me/<ваш_бот>`)

Подписки:
- Basic: 50 генераций/мес — 269 ₽
- Pro: 200 генераций/мес — 529 ₽

### Миграции БД
- При запуске `python bot.py` применяются автоматические миграции (в т.ч. добавление `updated_at` в `payments`, тарифы/квоты).
- Если база уже существовала ранее, достаточно перезапустить бота, чтобы миграции применились.

### Отдельный архив-бот

- Использует токен `BOT_TOKEN_ZIP` (добавьте в `.env`).
- Запуск: `python bot_zip.py`
- Поддержка:
  - Распаковка ZIP: отправьте архив — бот вернёт файлы.
  - Упаковка ZIP: `/start_pack`, отправляйте файлы, `/finish` — получить ZIP, `/cancel` — сброс.

## Использование

1. Отправьте боту документ в одном из поддерживаемых форматов
2. Бот автоматически извлечет текст из документа
3. Бот создаст саммари документа с помощью DeepSeek AI
4. Вы получите краткое содержание документа

## Дополнительные функции

- **Секретное слово "noool"**: Отправьте это слово боту, чтобы обнулить счетчик операций (для тестирования)
- **Лимит операций**: Бесплатные пользователи имеют 5 операций. После этого необходимо оформить подписку

## Технические детали

- Использует библиотеки для извлечения текста из различных форматов
- Разбивает большие документы на части для обработки
- Рекурсивно объединяет саммари для получения финального результата
- Сохраняет историю операций в базе данных SQLite


## Структура БД (SQLite, файл `bot_database.db`)

База создаётся и мигрируется автоматически при запуске `python bot.py` (функция `init_database()`):
- `users` — пользователи Telegram (user_id, username, first_name, last_name, created_at, updated_at).
- `operations` — лог генераций (user_id, operation_type, file_name, file_type, status, created_at).
- `subscriptions` — активная подписка пользователя (subscription_type: free/basic/pro, start_date, end_date, is_active, auto_renewal).
- `subscription_plans` — справочник тарифов (plan_type, monthly_limit, price_rub).
- `user_quotas` — остаток генераций по текущему плану (remaining, last_reset). Авто-ресет раз в календарный месяц.
- `payment_methods` — сохранённые реквизиты для автопродления (card_number, holder, expiry, cvv, bank_name, is_default).
- `payments` — платежи (amount, currency, status, transaction_id, updated_at, plan_type).

Основные процессы:
- При первом запросе к боту создаются `users`, бесплатная подписка и квота (5 генераций в месяц).
- Перед каждой генерацией проверяется квота (`check_operations_quota`); при успехе списывается 1 генерация (`consume_generation`).
- Активация подписки (Basic/Pro) обновляет запись в `subscriptions` и квоту до лимита плана.
- Платежи создаются через YooKassa (`payments`), статус обновляется после проверки; при `succeeded` подписка активируется.

## Отдельный сервис биллинга и отчётов (`billing_service.py`)

Функции (запускать по cron/systemd):
- Ежедневно: продление подписок (от «сегодня» +1 календарный месяц), до 3 попыток в течение 3 дней, с лимитом параллельных запросов (по умолчанию 4). Перед новым платежом проверяется последний: если `pending` <24ч — ждём; если >24ч — создаём новый.
- При успехе продления: обновление подписки и квоты, уведомление пользователю, уведомление админам. При неуспехе после ретраев — уведомление, предложение сменить способ оплаты, перевод на Free и квота 5/мес.
- Месячный сброс квот (по схеме `last_reset + 1 месяц`) для всех планов, включая Free.
- Ежедневный отчёт в 22:00 (локальное время сервера) админам:
  - Заголовок: `ОТЧЕТ_БОТ_САММАРИЗАЦИЯ <дата>`
  - Количество пользователей: Q всего (+N), W free (+N) | E basic (+N) | R pro (+N)
  - Генерации: I всего; T успех | Y фейл (% Y/I, если формат поддержан, но ошибка)
  - Оплаты: сумма N ₽; платежи успех X / фейл Y / pending Z; ретраи 2-я R2, 3-я R3; ошибки YooKassa (агрегат статусов)
- Рассылки от админов: реклама (текст/фото+текст), сообщения о техработах (запуск вручную администратором).

Запуск (обычно по расписанию через cron/systemd или просто запустите и оставьте работать):
```bash
# Полный цикл: продление + квоты + отчёт
python billing_service.py --task all

# Только продления/квоты
python billing_service.py --task renew

# Только отчёт
python billing_service.py --task report

# Рассылка рекламы/техработ (ручной запуск администратором)
python billing_service.py --task broadcast --text "Сообщение"
# с фото
python billing_service.py --task broadcast --text "Сообщение" --photo path_to_file

# Фоновый режим без внешнего планировщика (запустить и оставить работать)
python billing_service.py --task service
```

Cron-пример (ежедневно 22:00):
```
0 22 * * * /usr/bin/python /path/to/billing_service.py --task all >> /var/log/billing_service.log 2>&1
```

Переменные окружения для сервиса:
- `BOT_TOKEN` — токен основного бота (для уведомлений).
- `ADMINS` — список `user_id` администраторов через запятую.
- `REPORT_TIME` — время отчёта (по умолчанию `22:00`), локальное время сервера.
- `BILLING_CONCURRENCY` — лимит одновременных запросов к YooKassa (по умолчанию 4).
